# Nolane Browser Companion 0.2.10 — Live Chrome Surface

This release adds **Live Chrome Surface**. It does not try to load the remote website inside an iframe. Instead, it captures the actual active Chrome tab as a video-and-audio stream and renders that stream on the Nolane canvas. Pointer and keyboard events are sent back through Chrome DevTools Protocol (CDP) when Chrome permits debugger attachment; otherwise the canvas explicitly enters view-only mode. Version 0.2.10 also hardens input backpressure: when Chrome is busy, superseded pointer positions are acknowledged as dropped immediately, while discrete clicks, wheel events and keyboard commands retain their ordering.

## Install / replace the previous version

1. Download the latest repository ZIP from GitHub and extract it.
2. Open chrome://extensions.
3. Remove the old **Nolane Browser Companion** extension.
4. Enable Developer mode and choose **Load unpacked**.
5. Select the new repository's extension/ folder.
6. Keep https://nolane-x.github.io/web-view/ open in one Chrome tab and refresh it.
7. Open the website you want to place inside Nolane (for example YouPass) in a separate normal Chrome tab, and sign in there as usual.
8. While the website tab is active, click the Nolane Companion toolbar icon and choose **Stream this tab to Nolane**.
9. By default, the existing Nolane tab is moved into a second Chrome window. On sufficiently wide normal windows, Nolane is automatically placed alongside the source page without resizing the website's viewport; on smaller or maximized windows, Chrome's default placement is used. The website stays selected in its original window, which helps sites that pause when their tab becomes hidden. Keep both windows unminimized and do not fully cover the source window. Uncheck **Keep source page visible** to use the older single-window workflow. The page appears as an interactive surface when CDP is available, or a clearly labelled view-only surface when Chrome blocks debugger access.

The capture action must be started from the active source website tab. This is deliberate: Chrome's activeTab grant and tab capture are user-invoked capabilities. A background tab cannot be captured without an explicit user action.

## Powerful permission warning — read this before installing

Version 0.2.10 requires activeTab, tabCapture and **debugger**. Chrome will display strong permission warnings. In particular, its debugger permission can technically access the page debugger backend and read/change data on websites. tabCapture is also classified as broad access by Chrome's warning UI. The debugger is now an optional capability at runtime: when Chrome refuses CDP access, Nolane still attempts local video capture and falls back to a view-only card.

The implementation's intended path is narrower than the permission itself: the user starts capture from the currently active tab; the service worker records that source tab ID, the designated Nolane consumer-tab ID, the user's local browser-profile ID and the source origin; its CDP handler exposes only fixed viewport, mouse, keyboard and text-input operations. CDP is optional and a failed attachment cannot block the independent tabCapture video path. The source tab's top-level URL is monitored with chrome.tabs.onUpdated, so a cross-origin navigation stops the stream even in view-only mode. By default, Nolane moves its existing tab into a second Chrome window and leaves the website selected in its original window; this can prevent apps from seeing a hidden tab, but both windows must remain unminimized and the source must not be fully covered. The popup now includes a local **Website Compatibility Engine**. When it identifies a safe action, the result panel exposes an **Apply** button: it can send a refresh request to the existing live surface, focus the source page, or start a new capture if the prior track ended. The service worker independently recomputes the recommended action and rejects stale or mismatched commands; the workspace page cannot invoke capture or restart a source tab directly. Click **Analyze this website** to classify the active tab from its origin/path, inspect Chrome capture state and the active Nolane session, then receive a specific diagnosis and next actions. It recognizes common families such as media, meetings, learning, collaboration, developer tools and dashboards; these labels are heuristic hints, not content inspection. It also distinguishes foreign-extension debugger failures, duplicate captures, permission failures, stream-token handoff errors, first-frame timeouts, decode errors, ended tracks, muted tracks and missing frames. A local per-origin history stores only the site origin, category, attempt/success/failure counts and recent health state, capped at 40 origins. It never stores full paths, query strings, cookies, credentials, page HTML or screenshots.
The popup can also copy a local compatibility report with capture lifecycle states, decoded video dimensions, frame rate, presented/dropped-frame counters, track state, video-health state and the last failure stage. While connected, the canvas watches decoded frames continuously: if no new frame reaches the compositor for 12 seconds, it marks the surface as stalled; it marks the surface healthy again when frames resume. The monitor pauses its stall timer when the workspace or card is hidden, and reports track mute/unmute separately. Health updates are sent locally to the extension and are refreshed at most every 15 seconds while healthy. The code does not call the Cookies API, Network domain, DOM snapshot, response-body or page-storage APIs. The compatibility engine uses only the active tab's URL metadata, Chrome capture status and Nolane's local session telemetry. When a local video presentation stops producing frames, Nolane performs one bounded automatic soft recovery by reattaching the same MediaStream to its video element. The toolbar also provides a manual **Refresh video** action, limited to three attempts per five minutes. This does not restart Chrome's tab capture or change the website's login session. If the underlying capture track has ended, the user must start a new capture from the Companion. The optional tabs permission remains separate and is only for listing/importing selected tab titles and URLs.

No capture stream, cookies, passwords, page HTML or screen image are uploaded to a server. The video-and-audio stream is consumed directly by the designated Nolane workspace tab. There is no WebRTC relay, STUN/TURN service, remote proxy, external database or server-side browser. Only install this unpacked extension if you trust this repository's source code.

## What the live surface supports

- The actual Chrome-rendered page, including its existing session, origin, cookies and storage (they remain inside the original tab).
- Mouse movement, clicks, right-click, wheel scrolling and keyboard events forwarded through CDP when the debugger can attach.
- Video-only mode when another extension iframe, an existing DevTools session or a Chromium restriction prevents debugger attachment. The canvas reports this mode explicitly, keeps the live video running and offers Focus source instead of claiming pointer/keyboard control.
- The source tab's top-level URL is monitored separately from CDP. Same-origin navigation is allowed; cross-origin navigation ends the stream in both interactive and view-only modes.
- Chrome's getCapturedTabs() state is checked before starting, so an existing capture is reported before the extension attempts another stream.
- Capture lifecycle events (pending, active, stopped and error) are tracked independently from the CDP controller.
- A frame watchdog reports no new compositor-presented frames after 12 seconds. It attempts one bounded local soft recovery, then leaves the card available for manual refresh. Manual refresh is limited to three attempts per five minutes; an ended capture track still requires a new user-started capture.
- The source page remains a real browser page; the canvas displays a video/control mirror. Up to three tabs can be live at once in a workspace; saved cards are not subject to this concurrent capture limit.
- Live surfaces are stopped when the source tab closes, capture ends, the debugger detaches, the top-level origin changes, the workspace is switched/deleted, or its canvas card is removed.
- The source viewport size is refreshed when Chrome reports a frame resize, so pointer coordinates stay aligned after resizing the browser window.
- A connection is not acknowledged until the canvas receives a decoded video frame. If Chrome creates a stream but does not deliver frames, the extension tears the partial session down and reports a specific error rather than showing a false success.
- Pointer commands are serialized through a bounded queue. Consecutive pointer-move events are coalesced, while clicks, wheel events and keyboard commands keep their order. Superseded move requests are resolved immediately, so slow debugger responses cannot retain an ever-growing list of per-frame waiters.
- Live sessions are released when the workspace tab is closed or reloaded, including detaching the source tab debugger session.
- If you already created a website card manually, importing/streaming the same website can bind that card to the original Chrome tab instead of creating a duplicate.
- Browser-level shortcuts such as Ctrl+W, Ctrl+L, Ctrl+Tab and Alt+F4 are blocked inside the mirror to prevent accidentally closing or navigating Chrome itself; use **Focus source** for browser chrome commands.

## Known limitations

- This is not a native WebContents child. Video encoding/capture/decoding adds latency and consumes CPU/GPU resources. Start with one surface and benchmark before using several.
- Chrome debugger attachment can conflict with DevTools already open for the source tab or with pages that contain frames injected by other extensions. Close DevTools and other page-debugging tools; for extension-injected frames, try a clean Chrome profile or disable extensions that add overlays/iframes to the target site. Even when CDP is blocked, video-only mode should remain available.
- Some websites may detect remote debugging or behave differently while attached.
- Browser-owned UI (address bar, permission prompts, file chooser, passkeys, some popup windows/download flows), protected DRM video and some OS-level dialogs cannot be fully represented in a video surface. Click **Focus source** to use them in the original tab.
- Chrome-only, minimum supported version 116. Protected pages such as chrome:// and Chrome Web Store pages cannot be streamed.
- Source tab must be active when you invoke the Companion. The stream can continue when you switch back to Nolane, but cannot be silently started on arbitrary background tabs.
- For a true native composited browser child, a future Windows host using WebView2 Composition Controller is a better architectural endpoint. Its profile is separate from Chrome and does not automatically inherit Chrome login sessions.
